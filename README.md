# AirbnbCrawl

Fetch Airbnb prices for specific dates, then publish a static pitch site so a group can compare and pick a house.

## Workflow

```bash
uv sync
uv run main.py                                   # inputs.csv -> results.csv + raw/run_*.json
uv run split_raw.py raw/run_<timestamp>.json     # optional: one JSON per date range
uv run build_site.py                             # raw/*.json -> docs/data/model.json
```

`main.py` needs `OMKAR_API_KEY=...` in `.env` (gitignored). Each row of `inputs.csv` is one API request.

## Site (`docs/`)

One HTML page and one data model; everything is rendered in the browser.

| Path | What |
|---|---|
| `index.html` | The only page. The URL picks the view (below) |
| `data/model.json` | Generated by `build_site.py`: trip, date ranges, houses, price per house per date |
| `assets/pitch.js` | Pitch component: renders one house on one date range into a `<div>` |
| `assets/timeline.js` | Weekend plan on the overview: drag/resize activity blocks, saved per browser, "Copy link" shares it (`?plan=`) |
| `assets/app.js` | Views: overview, date page (one block per house, sorted by price), single pitch |
| `assets/style.css` | Styles |
| `images/<listing_id>/` | Your photos |

Views:

- `./` overview plan: date options, team picks, price-per-person matrix, areas
- `./?dates=2026-11-14_2026-11-16` every house for those dates as a block, price low → high (`&sort=desc` for high → low)
- `./?dates=2026-11-14_2026-11-16&id=1040827055809906305` one-page pitch

Use a pitch anywhere (another page in this site or elsewhere that can reach it):

```html
<div data-pitch="1040827055809906305" data-dates="2026-11-14_2026-11-16"></div>
<script type="module" src="assets/pitch.js"></script>
```

The pitch adapts to its container width, so the same block works full-page or as a scrollable
block on the date page. The site has to be served over http (GitHub Pages, or
`python3 -m http.server -d docs`); opening `index.html` as a file can't load the model.

## Photos

Put images in `docs/images/<listing_id>/` (jpg/png/webp). Files are used in name order:
the first is the hero, the next four fill the gallery. Rebuild after adding them
(the model stores the file names). A full `https://` URL in a listing's `photos` also works.

## Notes and title

- Team notes come from the `note` column of `inputs.csv`.
- Trip title and the city → area grouping are at the top of `build_site.py`.

## Deploy to GitHub Pages

1. Push this repo to GitHub.
2. Settings → Pages → Build and deployment → Source: *Deploy from a branch*, Branch: `main`, folder: `/docs`.
3. Rebuild and push whenever prices are refreshed.

The Pages site is public even if the repo is private (outside GitHub Enterprise), so anyone with the link
can see prices and notes. `raw/`, `results*.csv` and `.env` are gitignored and never published.
